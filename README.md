# dsh-mcloud

把 **中国移动云盘（139）** 接进 DeepSeek Harness：既给模型提供工具，也在**会话页顶部标签栏**放一个可见可点的面板。

面板以 `conversation.view` 槽位注册（`order: 30`），会作为**一个额外的页签**出现在会话页
「对话 / 轨迹 / …」那一排里。具体排在哪个位置取决于你装了哪些插件、以及它们的 `order` 值——
本插件用 30，比内置页签（0 / 10 / 20）靠后。

```
对话(0) · 轨迹(10) · [其他插件…] · 移动云盘(30)
```

> 接口随时可能变更或失效。上传的令牌以本地加密方式保管，**只存在你自己的机器上**。

## 快速开始

**第一次用，从登录开始：**

1. **装插件** → `dsh plugin --profile desktop add github:<owner>/dsh-mcloud`
2. **重启 DSH**（插件在 profile 启动时加载）
3. **打开面板** → 会话页顶部标签栏点「移动云盘」
4. **授权** → 浏览器登录 <https://yun.139.com/>，F12 抄 `Authorization`，粘进面板（详见下方「授权」）
5. **看到容量和文件列表** → 可以用了

之后任何时候都能让 AI 直接操作网盘（`mcloud_*` 工具），或者用面板右键菜单点点点。

## 安装

从 GitHub 装（推荐）：

```powershell
dsh plugin --profile desktop add github:<你的用户名>/dsh-mcloud
```

或本地开发时用 link：

```powershell
dsh plugin --profile desktop add "link:/path/to/dsh-mcloud"
```

装完**重启 profile 的 Web 服务**（插件在 profile 启动时加载）。改代码之后也要重启才生效。

## 授权（唯一的手工步骤）

1. 浏览器登录 <https://yun.139.com/>
2. `F12` → **网络(Network)** → 筛选 Fetch/XHR → 点 `hcy/file/list` 请求
3. 复制请求头 `Authorization` 里 **`Basic ` 后面那一串**（不要带 `Basic`）
4. 粘到面板 → 保存并验证

`Authorization` 是 `base64("pc:账号:令牌|…|到期毫秒")`。插件会看到期时间，快到期（<15 天）自动调 `authTokenRefresh.do` 续期并写回本地，所以**正常只需要抄这一次**。

### `ud_id` 不用管

容量接口要 `userDomainId`（Cookie 里的 `ud_id`）。OpenList 的驱动在没有它就拒绝查询，但那**只是它自己的保守判断**——实测**不填 `ud_id` 也能拿到容量**，所以面板上那一栏留空即可。

### 性能：点文件夹为什么曾经很慢

实测（网盘里 100 项的 `手机图片` 目录）：

| 配置 | 耗时 |
| --- | --- |
| 100 项 + 要缩略图（旧） | 3000~9000 ms，**还经常 ECONNRESET** |
| 100 项 + 不要缩略图 | 约 6000 ms |
| **30 项 + 不要缩略图 + 缓存（现在）** | **首屏 ~2.4 秒，回访 2~3 毫秒** |

三处改动：

1. **不再请求缩略图**（`imageThumbnailStyleList`）。这是最大的一刀：100 张图请求缩略图时服务端会直接
   RST 掉连接。而本插件界面根本不显示缩略图，属于纯浪费。
2. **分页默认只要 10 项**。这个接口对「一次要多少条」极度敏感，几乎二次方恶化：

   | pageSize | 中位耗时 |
   | --- | --- |
   | **10** | **1353 ms** |
   | 20 | 6631 ms |
   | 30 | 13692 ms |
   | 50 | 16088 ms |
   | 100 | 25311 ms（还超时/断连）|

   所以首屏只要 10 项，剩下的靠「加载更多」按需拉。
3. **两级缓存**：
   - Host 端 60 秒 LRU（任何写操作立即清空，绝不给旧数据）
   - 客户端 5 分钟「秒开」缓存，命中后**立刻渲染**再后台校准（stale-while-revalidate）

**优化后实测（100 项的大目录）**：

```
首屏 #1  2349 ms（服务端冷启动）
首屏 #2   497 ms
首屏 #3   411 ms   ← 稳定
缓存命中    2 ms
翻页     324 / 290 ms
```



### 账号显示

面板只显示**脱敏**账号，形如 `138******00` —— **只露前 3 位和后 2 位，中间全部隐藏**，任何情况下都不显示完整手机号。

> 为什么不做「显示名字」：移动云盘没有能查昵称的接口 —— `/user/info`、`/user/getUserInfo` 这些试过，全是「资源不存在」，
> 而 `Authorization` 里带的账号本身就是个手机号，没别的东西可挖。

### 进度条的账怎么算

每个文件对进度的贡献**恒等于它的字节数** —— 不管是真传了、**秒传**了，还是服务端压根没给分片地址。
（早期版本秒传的文件不计入进度，导致「已完成」却卡在 54.9% 到不了 100%，已修。）

已完成的任务一律显示 100%；失败的任务**不画进度条**，只显示失败原因。

### 凭据存在哪

`%USERPROFILE%\.dsh-mcloud\authorization.dpapi` —— **当前用户 DPAPI 加密**，换用户或换机器都解不开。想换目录在 `cordis.patch.yml` 里写 `config.credentialDir`。

## 传输（上传 / 下载）

面板上的「传输」区会实时显示进度条，可以取消。下载落地目录由「下载目录」决定（默认 `~/Downloads/dsh-mcloud`，可在面板改，存 localStorage）。

### 上传

**入口全在右键菜单里**（面板上没有上传卡片了），三种方式：

| 方式 | 怎么用 | 字节怎么走 |
| --- | --- | --- |
| **上传文件** | 右键 → 上传文件 → **浏览器原生文件对话框**（可多选） | 磁盘 → 浏览器 → 宿主端 → 网盘 |
| **上传文件夹** | 右键 → 上传文件夹 → **浏览器原生文件夹选择器**，保留目录结构 | 同上，逐个文件 |
| **拖动上传** | 右键 → 拖动上传 → 弹出面板 → 把文件拖进大虚线区 | 同上 |

三者走的是同一条通道：原始字节 POST 到 `/upload-body` → 宿主端落临时文件 → 分片上传 → 删临时文件。

> ⚠️ **代价说清楚**：这三条路都会**多走一趟本地拷贝**（磁盘 → 浏览器 → 宿主端 → 网盘）。
> 大文件想省掉这一趟，就让模型调用 `mcloud_upload(localPath)` 工具 —— 那条路是宿主端**直接从磁盘读到网盘**，
> 一次多余拷贝都没有（分片流式 PUT，不把文件读进内存）。
>
> **为什么不用宿主端弹系统对话框？** 试过，见「实现说明」第 4 条：在 DSH 宿主进程里 spawn 出来的
> PowerShell 会**秒退**，对话框根本建不出来。浏览器原生选择器没有这些问题。



> **为什么「选文件」按钮不走浏览器上传？**
> 浏览器给网页的只是一个 `File` 对象，**拿不到磁盘真实路径**，大文件还得从「磁盘 → 浏览器 → 宿主端」白拷一遍。
> 所以这几个按钮是**宿主端自己弹的系统对话框**，拿到真实路径后直接从磁盘流式读，**一次拷贝都不多花**。

> **拖拽为什么要多拷一份？**
> 拖进来的东西浏览器只给字节、不给路径，没有别的办法。宿主端会先把请求体落到**临时文件**，
> 走完正常上传流程再删掉。小文件无所谓，几个 GB 的话建议用「选择文件…」。

- 自动分片（默认 100MB，>30GB 用 512MB）、整文件 SHA256、**命中秒传就不真的传数据**
- 分片用流式 PUT，**不会把文件读进内存**
- 上传文件夹时，远端会按同样的目录结构建好；**同名文件夹复用，不会重复创建**
- 拖拽区不支持拖文件夹（浏览器限制），拖了会提示你用「选择文件夹…」

### 下载文件夹

移动云盘**没有打包下载的公开接口**（OpenList 的驱动遇到目录直接返回 `NotFile`），所以「下载整个文件夹」是
**递归遍历 → 逐个文件下载 → 本地还原目录结构**。文件多会比较慢，任务里能看到当前传到哪个文件。

## 写入与审批

这些会改动内容或往本机写文件，**每次都要过 Harness 审批**（面板按钮也会先 `confirm`）：

`mcloud_mkdir` `mcloud_rename` `mcloud_move` `mcloud_remove` `mcloud_upload` `mcloud_download` `mcloud_download_folder`

删除是**移进回收站**，不是永久删除。

## 实现说明

移动云盘**没有官方 MCP**，这里是按社区逆向出来的 `personal_new`（新的个人盘）接口实现的。协议参考：

- [OpenList](https://github.com/OpenListTeam/OpenList) 的 `drivers/139`（AGPL-3.0）
- [kong-hen/cloud_driver_sdk](https://github.com/kong-hen/cloud_driver_sdk) 的 `Yun139`
- [OpenList 139 驱动文档](https://doc.oplist.org/guide/drivers/139)

三个最容易踩的点：

1. **`Mcloud-Sign` 必须对「实际发出去的那个 JSON 字符串」签名。**
   `encodeURIComponent(body)` → 逐字符排序 → base64 → `md5(b64) + md5("ts:rand")` → 再 `md5` 取大写。
   签名和 body 一旦不是同一个字符串就必挂，所以代码里只 marshal 一次、两处共用。
2. **业务 host 要动态解析。** 先 `POST /user/route/qryRoutePolicy` 问 `modName === "personal"` 的 `httpsUrl`，问不到才回落到 `https://personal-kd-njs.yun.139.com/hcy`。
3. **上传是「建任务 → 分片 PUT → complete」三段式**，分片地址由服务端给（移动自己的 EOS 对象存储）。超过 100 片要再调 `/file/getUploadUrl` 分批取地址。

4. **宿主端弹系统对话框：试过，放弃了。** 走过完整的弯路，记录在这免得再踩：
   - 对话框会比浏览器窗口低（Windows 前台锁定不允许后台进程抢焦点）→ 用 `SetWindowPos(HWND_TOPMOST)` + WinForms `Timer` 顶上去，**量过 z 序确实生效**；
   - 传 1x1 的 helper 窗体当 owner 会把对话框**居中到 owner 上**、挤到屏幕左上角（用户看到的「白色长方形」）→ 改成不加 owner；
   - 定时器只找 6 秒会在机器忙时早退 → 改成 60 秒。
   - **最后卡死在环境上**：同一个脚本、同样的 `-Command` 调用，从普通 shell 启动时进程存活（对话框正常），
     但从 **DSH 宿主进程**启动时 **PowerShell 0.26 秒就退出**、对话框根本建不出来。
     实测方式是后台监听进程表：用户点击后确实新出现了一个 powershell 进程，250ms 后就没了。
   - **结论：改成浏览器原生 `<input type="file">`** —— 不需要 spawn / 抢焦点 / 窗口层级，整类问题一次性消失。
     代价是字节多走一趟本地拷贝，拿「按路径上传」的工具补回来。
